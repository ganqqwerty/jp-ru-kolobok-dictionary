# F100 — Проверка 100 новых статей в основном потоке

F100-1 — Пользователь запросил перевод Luna и внимательную проверку всех результатов основным оркестратором, без замены этой проверки рецензией Luna. Переводческий промпт: v8; классификатор: v7. Исходник: официальный XML 2026-07-05. Выборка не пересекается с прежним пилотом 193.

F100-2 — Состав: 40 шаблонов, 20 статей с пометой suffix, 40 словосочетаний и предложений. Категории служат только для отбора. Наличие пометы suffix не означает, что все значения статьи — суффиксальные. Состав и хеши сохранены в work/wadoku-xml/focus100/scope.json. Seed: wadoku-focus100-v1.

F100-3 — До перевода просмотрены исходные значения всех 100 статей. Особое внимание при проверке: включительная граница 五歳以上; конфликт времени в …して幸いです; участники действия …の渦中にまき込まれる; прагматика …したがる; регистр 味噌もくそも一緒である; открытые слоты и префиксы с многоточием справа. Это вопросы для проверки, ещё не выводы об ошибках перевода.

F100-4 — Найдена ошибка управления классификацией: отвергнутый ответ блокировал следующую порцию. Добавлены максимум три попытки на запрос и обратная связь валидатора. Исходный запрос и все ответы сохраняются; фактический retry-промпт и схема получают хеши. Предельный контекст проверяется также после добавления обратной связи.

F100-5 — Перевод: run 19, 100 статей, 279 фрагментов, промпт v8. Короткие статьи теперь пакуются вместе по лимиту 24 000 байт, а не принудительно по одной. Получилось 38 исходных заданий. Параллелизм перевода — 3, резерв полного контекста — 128 000. Старые прогоны сохраняют прежнюю упаковку; новый параметр сохранён в limits_json.

F100-6 — Классификация run 18: 98 допустимых ответов, две статьи (435810, 4303500) исчерпали три попытки. Для них перевод run 19 использует исходник без принятия ошибочной структуры; это явно записано в limits_json. Такой результат нельзя считать готовым Yomitan-словарём. Рецензирование переводов Luna не запускалось.

## F100-C — Проблемы структуры, не перевода

F100-C1 — 7652194: 運悪く…する получил alias する. 8438681: 何ひとつ…ない получил alias ない. Валидатор принял оба результата, хотя они теряют важную фиксированную часть конструкции. Поиск по обычным する и ない будет давать нерелевантные статьи. Нужна проверка, что отброшен только открытый слот, а не фиксированный лексический материал. Одного списка запрещённых коротких слов недостаточно.

F100-C2 — Правые открытые слоты не представлены отдельным видом alias. 牛…, 新…, 産…, チオ… остались без безопасного варианта поиска; すみませんが… и 最… исчерпали повторы. Нужен отдельный контракт для фиксированного начала, а не попытка объявить его полным раскрытием или суффиксом. Само наличие многоточия не означает, что его нужно заполнить выдуманным словом.

F100-C3 — 2689575: классификатор назвал できる дополнительным лексическим материалом в 識別できる и оставил самостоятельную статью. Это требует проверки как продуктивная форма возможности 識別する. Промпту классификации нужны контрастные примеры грамматической возможности и настоящего добавленного существительного/дополнения. Одного правила «есть дополнительный материал — отдельная статья» мало.

F100-C4 — Девять записей получили inherit_parent, но владельцы лежат вне выбранных 100. Родители доступны как исходный контекст, но это не равно наличию их перевода в прогоне. Для контрольного перевода это допустимо; для сборки нужен явно учтённый набор зависимостей. Нельзя молча добавить родителей к числу «100 проверенных статей» или заменить владельцев непроверенным текстом.

F100-C5 — Причины классификатора иногда написаны по-немецки, по-английски или по-китайски, несмотря на запрос русского языка. Это не ошибка русского словаря: данные служебные. Но такой отчёт сложнее проверять. Требование языка следует уточнить без запуска новой классификации только ради косметической правки.

## F100-T — Замечания к переводу

F100-T1 — 7331325, …して幸いです, translation 1323: «с нетерпением ждать возможности …», high. Luna перенесла будущее ожидание из немецкого sich darauf freuen в японскую конструкцию радости по поводу действия. Здесь нужен как минимум флаг конфликта японского и немецкого текста, а не уверенный перевод. Следующий фрагмент 1324 «быть рад(ым/ой) …» сам по себе не исправляет первое значение.

F100-T2 — 10009572, …と言ったらありゃしない, translation 1330: первый вариант «… — это ещё мягко сказано!» удачен. Второй — «… — это ещё далеко не всё!» — добавляет другой смысл: неполноту перечня вместо усиления оценки. Это уже не просто лишний синоним. Промпту нужна проверка каждого русского варианта по функции конструкции.

F100-T3 — 6272604, 崩れ, translation 1290: исходная служебная строка Nominalsuff. стала «именной суффикс со значением “несостоявшийся …”, “бывший …, утративший положение”». Соседний glossary 1291 уже передаёт эти значения. Luna развернула структурное описание в повторный перевод. Аналогичное повторение в 8403041, ちょう: пары 1312/1313, 1314/1315, 1316/1317, 1318/1319 и 1320/1321 практически дублируются. Нужны короткий перевод служебных descr и явный контракт совместного отображения glossary + definition; не произвольное удаление одного поля.

F100-T4 — 7380180, …を感知する, translation 1325: семь почти механических эквивалентов с повтором «что-либо». Формально источник покрыт, но словарная статья перегружена. Промпт v8 уже просит объединять синонимы, однако разрешённый массив из 1–12 элементов оставляет слишком широкий коридор. Лучше 2–4 содержательных эквивалента по умолчанию с исключением для действительно разных оттенков.

F100-T5 — 7434807, 女房孝行の, translation 1326: «преданный своей жене; послушный своей жене». Второй вариант следует немецкому gehorchend, но требует проверки по японскому 孝行: забота/хорошее отношение не тождественны послушанию. Это подозрение на конфликт исходных языков, а не доказанная ошибка перевода немецкого. В итоговом решении нужно сохранить это различие.

F100-S1 — Для проверки спорных выводов использованы также внешние источники, не переданные переводчику. Объяснение усилительной функции といったらありゃしない есть в [исследовании университета Рицумэйкан](https://www.ritsumei.ac.jp/acd/re/k-rsc/lcs/kiyou/pdf_22-2/RitsIILCS_22.2pp.145-179Tanaka.pdf). Значения 幸い как благополучия/удачи и формулы благодарной просьбы см. в [デジタル大辞泉 на Kotobank](https://kotobank.jp/word/%E5%B9%B8%E3%81%84-508686). Эти источники помогают проверить гипотезы, но не дают разрешения молча переписать конфликтный XML.

F100-T6 — 6585866, 系, translations 1390–1393: «система (System)», «следствие доказанной теоремы (Korrolar, Korrolarium, Satz)». 8052759, 弾, translations 1423–1424: «Homerun — удар…», «Tor — гол». Это обычные немецкие слова в русском результате, не защищённые имена. Они прошли с high несмотря на прямой запрет WTR-19. Повторить запрет ещё раз недостаточно: уже существующий source_echo_warnings должен давать адресную обратную связь и ограниченный повтор, с исключениями для защищённых имён, обозначений и этимонов.

F100-T7 — 10672891, 間, translation 1405: «… длиной», хотя соседнее исходное уточнение zeitlich прямо задаёт время. Для учебной статьи уместнее передать длительность: «в течение …» / «длительностью …», с учётом формы целого выражения. Это пример недостаточного использования локального контекста, а не потери XML парсером.

F100-G1 — Положительный контроль: 9038905, 五歳以上の子供, translation 1376: «дети пяти лет и старше», low с точным объяснением конфликта немецкого и японского. Здесь Luna выполнила нужное поведение: правильная включительная граница и явное предупреждение. Этот пример стоит использовать как образец решения конфликтов, но проверять новую версию на других числах и конструкциях.

F100-T8 — 4922578, …とは言いながら, translation 1472: «хотя и говоря …» вместо уступительной связки «хотя … / несмотря на то, что …». Немецкие obwohl, wenngleich также не требуют события говорения. Luna буквально разобрала часть устойчивой конструкции. Уступительное значение подтверждает [日本国語大辞典](https://kotobank.jp/word/%E3%81%A8%E3%81%AF%E3%81%84%E3%81%84%E3%81%AA%E3%81%8C%E3%82%89-2067832).

F100-T9 — 5200663, 締め, translation 1453: «закручивать; затягивать; завинчивать; закрывать; запирать». В исходнике это отглагольные существительные, внутри ветки als N.; сама Luna перевела её как «сущ.». Нужны названия действий, например «затягивание», а не инфинитивы. Это прямое нарушение WTR-4, хотя ответ получил high.

F100-T10 — 8653605, …したがる, translation 1477: «хотеть что-либо сделать; иметь склонность что-либо делать». Для учебной статьи не хватает пояснения наблюдаемого проявления желания. Нельзя сводить правило к абсолютному запрету первого лица: [исследование университета Отяномидзу](https://teapot.lib.ocha.ac.jp/record/39106/files/02_012-023.pdf) описывает различие точки зрения и внешнего проявления желания, а не только лица. Это недостаток грамматического объяснения, не полностью неверный базовый перевод.

F100-T11 — 1899530, …様, translation 1443: три почти одинаковых определения по полу адресата («почтительное обращение к мужчине…», «…женщине…», «…девушке…»). В рамках одного glossary_set это можно компактно объяснить как уважительный суффикс обращения без трёх повторов. Промпт не должен сохранять число немецких эквивалентов ради самого числа.

F100-T12 — 5175845, 公, translation 1512: источник этой единицы только Öffentlichkeit, а результат — «публика; герцог; князь». Последние два значения принадлежат соседней единице 1513. Это подтверждённое смешение значений, несмотря на WTR-17 и confidence=high. Каждый эквивалент надо проверять по собственному source_path, а контекст соседей использовать только для уточнения.

F100-T13 — 2530626, 土地成金が俗悪趣味の家を建てた。, translation 1524: «Нувориш — земельный спекулянт — построил себе дом вульгарного вкуса». Русский оборот «дом вульгарного вкуса» — неудачная калька. Смысл естественнее выразить через безвкусный дом или дом, построенный с дурным вкусом. Это редакционная проблема, не потеря содержания.

F100-C6 — У …かぎり примеры «пока жив» и «насколько мне известно» привязаны к sense 1 с переводом «по возможности / насколько возможно». Сами переводы примеров удачны, но временная и ограничительная функции не объяснены этим заголовком значения. Аналогично у 系 примеры принадлежности и происхождения стоят под общим «система». Нужна отдельная проверка совместимости примера с определением; хороший перевод примера не доказывает правильность его прикрепления.

## F100-P — Как улучшить следующий прогон

F100-P1 — Не дописывать ещё один длинный список запретов. Перестроить начало переводческого промпта в короткий порядок действий: определить функцию японской конструкции; сверить выбранный немецкий смысл; перевести только эту единицу; проверить каждый русский вариант обратным сопоставлением. Добавить несколько контрастных примеров для части речи, соседних значений, уступки и конфликта двух языков. Текущий v8 и результаты run 19 оставить неизменными как baseline.

F100-P2 — Для устойчивых конструкций явно требовать функциональный перевод, а не сумму отдельных слов. Для грамматической статьи — короткое объяснение употребления, если голый эквивалент вводит в заблуждение. Не придумывать отсутствующие участники, заполнения слотов и категоричные правила лица. При конфликте источника — low и конкретная причина, как в удачном случае 五歳以上, а не уверенное копирование немецкого.

F100-P3 — Добавить финальную проверку каждого элемента массива: подходит ли он тому же японскому употреблению и именно текущему source_path? Если он означает другую речевую функцию или взят из соседнего значения, его нельзя включать. По умолчанию достаточно 2–4 несходных по смыслу эквивалентов, часто одного. Больше — только при реальной необходимости, не ради соответствия немецкому списку.

F100-P4 — Часть правил должна выполнять программа. als N., als Suff., Nominalsuff. и подобные распознанные служебные строки следует обрабатывать как метаданные, не просить Luna разворачивать их в ещё одно определение. Для пары glossary + definition нужен единый контракт отображения; безопасное совпадение можно убрать при сборке, но нельзя удалять разные по смыслу куски по приблизительному сходству.

F100-P5 — Для утечки немецкого использовать существующий детектор как адресную обратную связь. В run 19 он нашёл шесть действительно плохих единиц (1390–1393, 1423–1424) и одно допустимое fp (1401). Поэтому безусловно запрещать латиницу нельзя. Проверять роль, защищённые фрагменты, обозначения и исходные слова; при неясности сохранять предупреждение. Повтор ограничить, не чинить перевод заменой строк в базе.

F100-P6 — В классификаторе и валидаторе отдельно исправить сохранение фиксированных частей шаблона, правые открытые слоты и продуктивные формы с できる. Не переносить эти правила в промпт перевода: переводчик не управляет lookup_aliases. Для проверки исправления использовать не только эти примеры, но и новые шаблоны с теми же типами риска.

F100-P7 — Следующий эксперимент: новая версия промпта, повтор небольшой группы подтверждённых ошибок, затем новый батч 100 статей с проверкой в основном потоке. Не выдавать устранение ошибки в уже известной статье за улучшение всего словаря. В этой задаче новый переводческий промпт ещё не применён, повторной смысловой правки переводов не было.

## F100-R — Итог и ограничения

F100-R1 — Прочитаны все 100 статей и все 279 переведённых фрагментов, включая 38 примеров с японским оригиналом. Проверены не только четыре low и один medium, но и 274 high. Существенные ошибки встречаются именно среди high. Структурная валидация прошла для всех 38 заданий; одному заданию понадобилась вторая попытка из-за немецких элементов массива без кириллицы. Это не языковое одобрение.

F100-R2 — Перевод создали 39 вызовов Luna: 38 заданий по 1–6 статей, один повтор. Учтённый расход перевода — 876 050 токенов (831 406 входных, 44 644 выходных). Максимальный вход одного вызова — 31 593 токена; резерв полного запроса — 128 000. Признаков переполнения контекста в этих вызовах нет.

F100-R3 — Классификация потребовала 114 вызовов и минимум 1 689 536 учтённых токенов. Для двух тайм-аутов расход неизвестен. Это дороже самого перевода по числу токенов: следующий цикл стоит удешевлять упаковкой небольших классификационных задач и повторным использованием точного неизменного контекста. Переводческие батчи уже перестали быть принудительно однословными.

F100-R4 — Это контрольный прогон, не готовый выпуск. Новая сборка Yomitan не выпускалась: остаются две неуспешные классификации, нерешённые lookup-решения и внешние владельцы. Прежний сайт не заменён результатом run 19. Все русские target_text этого прогона создала Luna; основной поток только проверял их и записывал замечания.

F100-R5 — Итоговый тест кода: 274 passed, 4 skipped; git diff --check без замечаний. Незавершённых вызовов Luna в run 18/19 нет. Анализ всех 100 статей записан в PostgreSQL для окна 1 с решением repair и хешем точного результата. Машинная копия решения: reports/wadoku_focus100_window1_analysis.json; полный исходно-переводной пакет: work/wadoku-xml/focus100/review-packet.json.
